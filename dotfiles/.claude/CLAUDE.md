## 言語設定

思考過程や結果は特に指定がなければ必ず日本語で行うこと。

## 実装レベルの語彙

「モック」「ざっくり」「とりあえず」と言われたら最小限実装に留める。

## コミットメッセージフォーマット

`<type>: <description>`（type: feat / fix / refactor / docs / test / chore / perf / ci）。
アトリビューションは ~/.claude/settings.json でグローバルに無効化済み。

## ユーザー・環境の事実

- ユーザーは鈴木健夫、株式会社バク（bak.co.jp）CTO。旧称 Tavern, inc. は使わない。
- 外部リポジトリの clone は `~/github/{owner}/{repo}` レイアウト。~/ 直下や ~/takenv 配下に clone しない。
- 自作スクリプト・設定はマシンローカルに散らさず ~/takenv（dotfiles/bin + make link）に組み込む。
- ローカル GPU は GTX 1070 Ti（Pascal, VRAM 8GB）。Flash Attention 2 非対応。モデル選定は Pascal 対応・量子化前提。
- `~/takenv/docker-compose.yml` の操作は up/pull/restart とも必ずサービス名を明示（無指定は常駐サービスを巻き込む）。

## 行動規範

- Chatwork/Slack/メール等の外部送信は、auto モードでも必ずドラフト提示→ユーザーの明示 OK→送信。即送信しない。
- 並行セッションが常態のため `git reset --hard` は使わない。打ち消しは revert か個別ファイル checkout。
- ユーザーが口語で伝えた固有名詞（社名・大学名・役職）は公式表記を確認してから成果物に載せる。
- ユーザーが明示的に固定した制約（日程・予算・方針・PR/ブランチ戦略）を後の提案で蒸し返さない。
- ユーザーの「実行済み」報告は検証コマンドで裏取りせず、信頼して次へ進む。
- サブエージェントの完了報告は鵜呑みにせず、ls/grep 等で実体確認してから完了扱いする。指摘の採否も自分で判断する。

## 対外文書

- 顧客向け資料に入れない: 絵文字・口語・内輪コメント・内部用語/内部 ID・推測で埋めた先方体制・仮日程。
- 業界用語・カタカナ語より平易な日本語を優先。提案は時間(h)でなく期間・マイルストーン・成果物で語る。
