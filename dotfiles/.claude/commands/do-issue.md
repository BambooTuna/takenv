与えられたissueのタスクを進めたい。

## 手順

1. issueの内容を読み、適切にdevelopからブランチを切る。

example. `$ git checkout -b (feat|fix)/hogehoge develop`
そしたら作業記録をしてほしい。

- コメントにブランチ名を記録する。
- 自分をissueにアサインする。

その後、最初だけ `$ make init` を実行する。

2. claude codeの /plan コマンドを使用しissueの内容を元にさらに詳しい計画を立てる。

計画が最初のissueの目的ややることからズレないように、余計に実装が増えたり減ったりしないように。最新の注意をしてほしい。

3. agent teamsを使用し、計画の妥当性、抜け漏れ、偽陰性、偽陽性がないかをレビューする。

issueにおける実装範囲や目的からのずれの検知をする監査役は絶対必要。

**3~5人ほどopusモデルで起動して多重チェックしてほしい。**

4. 必要に応じて tdd（t-wada） を使用して、実装を進める。

agent teamsを使用し、必ず実装は分担する(3~7人)。一人で全て実装するのはコンテキストが大きくなりすぎて、ミスの元になるため。

5. 実装を当初の計画などと照らし合わせたり、コード規約などをみたりしながらコードレビューを行う。tddであれば、t-wadaさんによる監査も必要。

agent teamsを使用し、必ず複数人でコードレビューを行うこと。セキュリティや品質の問題を見逃さないために、複数の視点からレビューすることが重要。
**偽陰性、偽陽性、抜け漏れチェックがないように注意すること。**

## 制約、注意点

- あなたはリーダーとして **判断** と **メンバーへの指示** のみを行ってください。
- 判断に困ったり、自信がない際は相談、議論相手として Agent teamsを利用して技術顧問や専門家を招集し議論を行ってください。
- AgentTeamsを使用する際は、判断、レビュー、監査を行うメンバーはopusを使用してください。haikuモデルは何においても使用禁止です。
- AgentTeamsで何人アサインするかはタスクの重要度やサイズに応じて変動させてほしい。簡単なタスクで5人でレビューするのは非効率だし、逆に重要なタスクで2人でレビューするのはリスクが高いです。
