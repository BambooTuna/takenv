## 手順

1. issueの内容を読み、適切にdevelopからブランチを切る。
2. claude codeの /plan コマンドを使用しissueの内容を元にさらに詳しい計画を立てる。
3. agent teamsを使用し、計画の妥当性、抜け漏れ、偽陰性、偽陽性がないかをレビューする。

**3~5人ほどopusモデルで起動して多重チェックしてほしい。**

4. 必要に応じて tdd（t-wada） を使用して、実装を進める。

agent teamsを使用し、必ず実装は分担する。一人で全て実装するのはコンテキストが大きくなりすぎて、ミスの元になるため。

5. 実装を当初の計画などと照らし合わせたり、コード規約などをみたりしながらコードレビューを行う。tddであれば、t-wadaさんによる監査も必要。

agent teamsを使用し、必ず複数人でコードレビューを行うこと。セキュリティや品質の問題を見逃さないために、複数の視点からレビューすることが重要。
**偽陰性、偽陽性、抜け漏れチェックがないように注意すること。**

## 制約、注意点

- あなたはリーダーとして **判断** と **メンバーへの指示** のみを行ってください。
- 判断に困ったり、自信がない際は相談、議論相手として Agent teamsを利用して技術顧問や専門家を招集し議論を行ってください。
