情報を集めて、今日やるべきことを整理します。

## 事前準備（必ず最初に実行）

1. `~/.claude/commands/morning-briefing/feedback.md` を Read で読み、過去のユーザー指摘を全て把握する。
2. 以降の手順・出力ルールに加えて、その指摘を必ず反映する。

## 手順

1. 今日の日付は `date "+%Y-%m-%d %H:%M:%S"` (JST) です。
2. SKILL(/gogcli) を使用し、昨日からの新規メールを取得する。
   - プロモーション・スパムは除外。
   - 受信トレイと送信済みの両方を見る（対応済みスレッドをTODOに混入させない）。
3. SKILL(/gogcli) を使用し、本日〜今週金曜のカレンダー予定を取得する（予定への準備が必要なため）。
4. PLUGIN(/slack) を使用し、昨日からのメッセージを取得する（自分・メンバー両方）。
5. 以上をまとめて TODO を作成する。

## 出力ルール（重要）

### 表示の濃淡を明確に分ける

ユーザーは「重要なものをすぐ拾える」状態を求めている。重要度の低い情報を等列に並べない。

| ランク | 内容 | 表示方法 |
|---|---|---|
| 🔴 クリティカル | 今日中に動かないと損失・信用毀損が出るもの（顧客返信、当日の予定準備、ホットリード初動） | **メイン領域**で全文記載 |
| 🟡 重要 | 今週中に処理すべき進行案件、論点準備 | **メイン領域**で全文記載 |
| ⚪ 低 / 参考 | 通知系・自動メール・社内連絡の事実確認のみ | **「その他（折りたたみ）」**として件名と1行サマリだけ。詳述しない |
| ❌ ノイズ | 海外営業勧誘、無関係なマーケメール、対応不要の通知 | **出力しない**（カウントもしない） |

- 「優先度低いけどOOがある」というぶら下げ列挙は禁止。重要なものだけが目に飛び込む構成にする。
- ⚪ 低ランクは `<details><summary>その他（N件）</summary>...</details>` か、1テーブルにまとめて末尾に置く。

### テーブルを多用する

箇条書きの羅列より、構造化されたテーブルを優先する。具体的には：

- **カレンダー**：日時 / 予定 / 備考 の 3 列テーブル
- **重要メール**：件名 / 差出人 / 状態 / 次アクション の 4 列テーブル
- **TODO**：# / 優先度 / タスク / 主担当 / 期限 の 5 列テーブル

文章でだらだら書くのは最小限。ヘッダで論点を区切る。

### 構成（推奨スケルトン）

```markdown
# 朝のブリーフィング — YYYY-MM-DD（曜）HH:MM JST

## 🔴 今日のクリティカル（最大3〜5件）
（テーブル or 短い箇条書きで、今日動かすべきことだけ）

## カレンダー（本日〜金曜）
（テーブル）

## 重要メール（🔴🟡のみ）
（テーブル + 必要なら短い補足）

## TODO 一覧
（テーブル：優先度順）

<details>
<summary>その他（参考・通知系 N件）</summary>
件名 / 1行サマリ だけ列挙
</details>

## 補足
取得失敗した情報源（例: Slack 未認証）や、ブリーフィングを使う側への注意事項を最小限。
```

### NG パターン

- 「🟢 対応不要」セクションに通知メールを並べる → 出力しない。
- 「AWS Health通知」「Notionの更新通知」「OpenAIの請求通知」など、読まなくても支障ないものを本文に書く → その他折りたたみへ、または完全に省略。
- 海外メディア掲載勧誘 (`startupcityapac` 等) → 触れない。
- 同じ事実を別セクションで繰り返す → 1度だけ。

## ユーザー指摘の反映フロー

1. 実行後、ユーザーが出力に対して指摘を出したら、その内容を `~/.claude/commands/morning-briefing/feedback.md` の「蓄積された指摘」セクションに追記する。
2. ただし「学習ではなくプロンプトに直接反映してほしい」と明示された場合は、このファイル（`morning-briefing.md`）を直接編集する。
3. 次回以降の `/morning-briefing` 実行時、事前準備で feedback.md を読むので自動で反映される。
