プロンプトログの定期棚卸しを行う。

直近 7 日間のユーザー手動プロンプトから繰り返しパターンを抽出し、
Skill / Command / Hook 化の候補を提案する。

## Step 1: プロンプトログの読み込み

`~/.claude/logs/prompts.jsonl` を読み、直近 7 日間のプロンプトを取得する。
ファイルが存在しない、または対象期間のレコードが 1 件もない場合は
「ログがまだ十分に溜まっていません」と報告して終了する。

## Step 2: 自動生成プロンプトの除外

以下に該当するプロンプトはスケジュール / タスク / スキルによる自動生成 (または特殊文脈) なので除外する。

- `#TASK` で始まるもの
- `<<autonomous-loop>>` / `<<autonomous-loop-dynamic>>` などのセンチネル
- 明らかにテンプレート的な長文プロンプト (手順番号付きで 100 行超など)
- この `/prompt-digest` を実行するためのプロンプト (自己言及の除外)
- すでに Skill / Command 名で始まる短いプロンプト (例: `/ship`, `/morning-briefing`) → これは「使用回数」として別途記録するが、新規候補からは外す

## Step 3: パターン分析

残ったユーザー手動プロンプトを「意図」でグルーピングする。
完全一致ではなく、同じ意図の異なる言い回しは同一パターンとして扱う。

例:
- 「commit して push して PR 作って」
- 「ship」「PR まで」
- 「修正を commit して、PR まで出して」
→ すべて `commit-push-pr-creation` パターン

3 回以上繰り返されているパターンを抽出する。

## Step 4: KVS への記録

検出したパターンを `~/.claude/logs/patterns.json` に追記する。
ファイルが無ければ `{}` で初期化する。

形式:

```json
{
  "<short-kebab-key>": {
    "count": 12,
    "last_seen": "2026-06-19",
    "examples": ["..."]
  }
}
```

- 既存 key は count をインクリメントし、`last_seen` を更新する
- `examples` は直近 6 件まで残し、古いものから捨てる
- 書き込みは jq などで原子的に行う (一時ファイルに書いて mv)

## Step 5: 制度化候補の報告

count >= 3 のパターンについて、次の形式で標準出力に報告する。

```
## 繰り返しパターン候補

### <pattern-name> (count: N, last_seen: YYYY-MM-DD)

例:
- "..."
- "..."

提案: Skill / Command / Hook のどれが適切か、1 行で
作るためのプロンプト案:
> ...
```

「作るためのプロンプト案」は、ユーザーがそのまま次のセッションで貼り付けて
Skill / Command / Hook を作れる粒度にする。
ただし作成自体はユーザー承認を経るまで行ってはならない。

## Step 6: 古いエントリの削除

count が 1 で `last_seen` が 30 日以上前のエントリは自動削除する。

## Step 7: サマリ

最後に 3-5 行で全体サマリを出す。

- 期間: 直近 7 日
- 対象プロンプト数: N 件 (除外: M 件)
- 新規検出パターン: K 件
- 既存パターンの更新: L 件
- 制度化候補: 上位 3 件の名前

## 制約

- ユーザー承認なしに Skill / Command / Hook / Schedule を作成・編集してはならない
- `~/.claude/logs/prompts.jsonl` には機微情報が含まれる可能性がある。報告時に長い example はそのまま貼らず必要に応じて要約する
- プロンプトログ自体の削除はこのコマンドではやらない (別途運用で扱う)
