# 開発ワークフロー

> このファイルは [common/git-workflow.md](./git-workflow.md) を、git操作前に行われる完全な機能開発プロセスで拡張する。

機能実装ワークフローは開発パイプラインを記述する: リサーチ、計画、TDD、コードレビュー、そしてgitへのコミット。

## 機能実装ワークフロー

0. **リサーチと再利用** _（新規実装前に必須）_
   - **まずGitHubコード検索:** 新しいコードを書く前に `gh search repos` と `gh search code` で既存の実装、テンプレート、パターンを探す。
   - **次にライブラリドキュメント:** Context7またはプライマリベンダーのドキュメントで、実装前にAPIの振る舞い、パッケージの使用法、バージョン固有の詳細を確認する。
   - **最初の2つで不十分な場合のみExa:** GitHubの検索とプライマリドキュメントの後、より広範なウェブリサーチやディスカバリーにExaを使用する。
   - **パッケージレジストリを確認:** ユーティリティコードを書く前にpnpm、PyPI、crates.ioなどのレジストリを検索する。手製のソリューションよりも実績のあるライブラリを優先する。
   - **適用可能な実装を検索:** 問題の80%以上を解決し、フォーク、ポート、ラップ可能なオープンソースプロジェクトを探す。
   - 要件を満たす場合、新規コードの作成より実績のあるアプローチの採用やポートを優先する。

1. **まず計画**
   - **planner** エージェントを使用して実装計画を作成
   - コーディング前に計画ドキュメントを生成: PRD、アーキテクチャ、システム設計、技術文書、タスクリスト
   - 依存関係とリスクを特定
   - フェーズに分割

2. **TDDアプローチ**
   - **tdd-guide** エージェントを使用
   - テストを先に書く（RED）
   - テストを通す実装（GREEN）
   - リファクタリング（IMPROVE）
   - 80%以上のカバレッジを確認

3. **コードレビュー**
   - コード記述直後に **code-reviewer** エージェントを使用
   - CRITICALとHIGHの問題に対処
   - 可能な場合MEDIUMの問題を修正

4. **コミット & プッシュ**
   - 詳細なコミットメッセージ
   - コンベンショナルコミットのフォーマットに従う
   - コミットメッセージフォーマットとPRプロセスについては [git-workflow.md](./git-workflow.md) を参照
