# コーディングスタイル

## イミュータビリティ

既存のオブジェクトをその場でミューテートせず、変更を含む新しいコピーを返す。隠れた副作用を防ぎ、デバッグを容易にする。

## ファイル構成

少数の大きなファイルより多数の小さなファイル:

- 高凝集・低結合。種類別ではなく機能/ドメイン別に整理
- 200-400行が一般的、最大800行。大きなモジュールからユーティリティを抽出

## エラーハンドリング

- エラーを黙って握りつぶさない。失敗時にデフォルト値で吸収しない
- UI 境界では意味のあるメッセージを出し、サーバー側ではエラーコンテキストをログに残す
- 過度な分岐や防御的 try/catch を足さない（プロジェクト側のエラー方針が優先）

## 入力バリデーション

- システム境界（ユーザー入力・外部 API・ファイル内容）でスキーマベースにバリデーションし、早期に失敗する

## 注意

プロジェクトの CLAUDE.md / rules と矛盾する場合はプロジェクト側を優先する。
