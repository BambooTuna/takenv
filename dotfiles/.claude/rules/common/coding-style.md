# コーディングスタイル

## イミュータビリティ（CRITICAL）

常に新しいオブジェクトを作成し、既存のものを絶対にミューテートしない:

```
// 擬似コード
間違い:  modify(original, field, value) → originalをその場で変更
正解: update(original, field, value) → 変更を含む新しいコピーを返す
```

理由: イミュータブルなデータは隠れた副作用を防ぎ、デバッグを容易にし、安全な並行処理を可能にする。

## ファイル構成

少数の大きなファイルより多数の小さなファイル:

- 高凝集・低結合
- 200-400行が一般的、最大800行
- 大きなモジュールからユーティリティを抽出
- 種類別ではなく機能/ドメイン別に整理

## エラーハンドリング

常にエラーを包括的に処理する:

- すべてのレベルでエラーを明示的に処理
- UI向けコードではユーザーフレンドリーなエラーメッセージを提供
- サーバー側で詳細なエラーコンテキストをログに記録
- エラーを黙って握りつぶさない

## 入力バリデーション

常にシステム境界でバリデーションする:

- すべてのユーザー入力を処理前にバリデーション
- 利用可能な場合はスキーマベースのバリデーションを使用
- 明確なエラーメッセージで早期に失敗
- 外部データを信頼しない（APIレスポンス、ユーザー入力、ファイル内容）

## コード品質チェックリスト

作業完了前に:

- [ ] コードが読みやすく適切に命名されている
- [ ] 関数が小さい（50行未満）
- [ ] ファイルが焦点を絞っている（800行未満）
- [ ] 深いネストがない（4レベル超）
- [ ] 適切なエラーハンドリング
- [ ] ハードコードされた値がない（定数または設定を使用）
- [ ] ミューテーションがない（イミュータブルパターンを使用）
