# チームビルダー

エージェントチームをAgent Teams機能（TeamCreate）で構成・実行するためのインタラクティブメニュー。ユーザーはリーダーとして指示と判断に徹し、選択されたエージェントがチームメートとして実装・レビュー・議論を行う。

## 使用場面

- 複数のエージェントペルソナ（markdownファイル）でチームを構成したい場合
- メンバーに実装を任せ、自分は指示と判断に徹したい場合
- エージェント同士が議論・相互レビューする必要がある場合
- 異なるドメインからアドホックチームを構成したい場合（例: DDD + フロントエンド + LLM）

## 前提条件

- Agent Teams機能の有効化が必要（環境変数 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`）
- エージェントファイルはペルソナプロンプトを含むmarkdownファイルであること
- frontmatterの `name` フィールドがエージェント名、`description` が説明として使用される

フラットとサブディレクトリの両方のレイアウトに対応:

**サブディレクトリレイアウト** — ドメインはフォルダ名から推定:

```
agents/
├── ddd/
│   ├── katojun.md
│   └── masuda.md
├── frontend/
│   ├── mizchi.md
│   └── catnose.md
└── llm/
    └── umiyuki.md
```

**フラットレイアウト** — 共通ファイル名プレフィックスからドメインを推定。2つ以上のファイルが共有するプレフィックスがドメインとなる。固有のプレフィックスを持つファイルは「General」に分類される:

```
agents/
├── ddd-katojun.md
├── ddd-masuda.md
├── frontend-mizchi.md
├── frontend-catnose.md
├── llm-umiyuki.md
├── architect.md        → General
└── code-reviewer.md    → General
```

## 設定

エージェントディレクトリは順番に探索され、結果はマージされる:

1. `./agents/**/*.md` + `./agents/*.md` — プロジェクトローカルのエージェント
2. `~/.claude/agents/**/*.md` + `~/.claude/agents/*.md` — グローバルエージェント

すべての場所からの結果はマージされ、エージェント名で重複排除される。同名の場合、プロジェクトローカルのエージェントがグローバルエージェントより優先される。

## 動作の仕組み

### ステップ1: 利用可能なエージェントの検出

上記の探索順序でエージェントディレクトリをGlobする。READMEファイルは除外。見つかった各ファイルに対して:

- **サブディレクトリレイアウト:** 親フォルダ名からドメインを抽出
- **フラットレイアウト:** すべてのファイル名プレフィックス（最初の `-` より前のテキスト）を収集。2つ以上のファイル名に含まれるプレフィックスのみドメインとして認定。固有のプレフィックスを持つファイルは「General」にグループ化
- frontmatterの `name` からエージェント名を抽出。なければ最初の `# 見出し`、それもなければファイル名から導出
- frontmatterの `description` から要約を抽出。なければ見出し後の最初の段落

すべての場所を探索してもエージェントファイルが見つからない場合、ユーザーに通知して停止。

### ステップ2: ドメインメニューの表示

```
利用可能なエージェントドメイン:
1. DDD (2) — かとじゅん, 増田亨
2. Frontend (2) — mizchi, catnose
3. LLM (1) — うみゆき
4. General (4) — architect, code-reviewer, planner, tdd-guide

ドメインまたは特定のエージェントを選択してください（例: "1,2" または "katojun + mizchi"）:
```

- エージェントがゼロのドメイン（空のディレクトリ）はスキップ
- ドメインごとのエージェント数を表示

### ステップ3: 選択の処理

柔軟な入力を受け付ける:

- 番号: "1,2" でDDDとFrontendの全エージェントを選択
- 名前: "katojun + mizchi" で検出されたエージェントにファジーマッチ
- "all from ddd" でそのドメインの全エージェントを選択

5つ以上のエージェントが選択された場合、リスト表示し、絞り込みを依頼: 「N個のエージェントが選択されました（最大5個）。残すものを選んでください。」

選択の確認:

```
選択済み: かとじゅん + 増田亨 + mizchi
作業内容を教えてください（タスクを記述）:
```

### ステップ4: Agent Teamsでチーム構成

1. **TeamCreateでチームを初期化する**
   ```
   TeamCreate({
     team_name: "{タスクに基づく名前}",
     description: "{タスクの説明}"
   })
   ```

2. **タスクの説明がまだ提供されていない場合、入力を求める**

3. **TaskCreateで各メンバーの担当タスクを作成する**
   - タスクの説明にはユーザーの要求を分解した具体的な作業内容を記載
   - 依存関係がある場合はタスク間の依存を設定

4. **選択された各エージェントをチームメートとしてスポーンする**
   - Agent toolで各メンバーをスポーン:
     ```
     Agent({
       name: "{エージェント名}",
       team_name: "{チーム名}",
       prompt: "{エージェントファイルの内容}\n\n## チームでの役割\nあなたはチームメートとして参加しています。\n- 担当タスクをTaskListで確認し、TaskUpdateでクレームして作業開始\n- 他のメンバーとSendMessageで直接議論可能\n- 作業完了時はTaskUpdateで完了をマーク\n- 判断が必要な場合はリーダー（ユーザー）にSendMessageで確認\n\n## タスク: {タスクの説明}"
     })
     ```
   - 各メンバーは並列でスポーン（独立しているため）

5. **リーダー（自分 = Claude）はオーケストレーションに徹する**
   - メンバーの進捗をTaskListで監視
   - メンバーからの質問・確認にはユーザーに判断を仰ぐ
   - メンバー間の対立はユーザーに報告し判断を求める
   - メンバーの成果物をユーザーに報告

### ステップ5: 進捗管理と報告

チーム稼働中:

- **TaskListで進捗を定期的に確認**
- **メンバーからのメッセージをユーザーに中継**（判断が必要な場合）
- **メンバー間の議論結果をサマリーしてユーザーに報告**

### ステップ6: 結果の統合

すべてのタスク完了後、統一レポートを提示:

- メンバーごとにグループ化された成果
- 以下をハイライトする統合セクション:
  - メンバー間の合意点
  - 推奨事項間の対立や緊張（あれば）
  - 推奨される次のステップ
- **TeamDeleteでチームをクリーンアップ**

1つのエージェントのみ選択された場合、統合をスキップして出力を直接提示。

## ユーザーの役割: リーダー

このスキルではユーザーはリーダーとして以下に徹する:

- **指示**: チームへのゴールと方針を示す
- **判断**: メンバーからの質問・確認に回答する
- **承認**: メンバーの成果物を承認/差し戻しする
- **調停**: メンバー間の意見対立を裁定する

ユーザーが自ら実装・調査を行う必要はない。すべてチームメートが実行する。

## ルール

- **動的検出のみ。** エージェントリストをハードコードしない。ディレクトリ内の新しいファイルはメニューに自動表示される。
- **チームあたり最大5エージェント。** 5つ以上は協調オーバーヘッドが増大し、トークン使用量が過大になる。選択時に強制する。
- **Agent Teams（TeamCreate）を使用。** 並列Agentコールではなく、TeamCreateでチームを構成し、メンバー同士がSendMessageで直接対話できるようにする。
- **リーダーはオーケストレーションのみ。** 実装・調査はすべてチームメートに委譲する。ユーザーへの判断要求のみリーダーが行う。
- **ファイル競合を回避。** 複数メンバーが同じファイルを編集しないよう、タスク分割時にファイル所有を明確にする。
- **チーム完了時にクリーンアップ。** 全タスク完了後、TeamDeleteでリソースを解放する。
