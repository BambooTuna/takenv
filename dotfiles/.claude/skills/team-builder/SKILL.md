# チームビルダー

エージェントチームをオンデマンドで閲覧・構成するためのインタラクティブメニュー。フラットまたはドメインサブディレクトリのエージェントコレクションに対応。

## 使用場面

- 複数のエージェントペルソナ（markdownファイル）があり、タスクに使用するものを選びたい場合
- 異なるドメインからアドホックチームを構成したい場合（例: セキュリティ + SEO + アーキテクチャ）
- 決定前に利用可能なエージェントを閲覧したい場合

## 前提条件

エージェントファイルはペルソナプロンプト（アイデンティティ、ルール、ワークフロー、成果物）を含むmarkdownファイルである必要がある。最初の `# 見出し` がエージェント名として、最初の段落が説明として使用される。

フラットとサブディレクトリの両方のレイアウトに対応:

**サブディレクトリレイアウト** — ドメインはフォルダ名から推定:

```
agents/
├── engineering/
│   ├── security-engineer.md
│   └── software-architect.md
├── marketing/
│   └── seo-specialist.md
└── sales/
    └── discovery-coach.md
```

**フラットレイアウト** — 共通ファイル名プレフィックスからドメインを推定。2つ以上のファイルが共有するプレフィックスがドメインとなる。固有のプレフィックスを持つファイルは「General」に分類される。注意: アルゴリズムは最初の `-` で分割するため、複数語のドメイン（例: `product-management`）にはサブディレクトリレイアウトを使用すること:

```
agents/
├── engineering-security-engineer.md
├── engineering-software-architect.md
├── marketing-seo-specialist.md
├── marketing-content-strategist.md
├── sales-discovery-coach.md
└── sales-outbound-strategist.md
```

## 設定

エージェントディレクトリは順番に探索され、結果はマージされる:

1. `./agents/**/*.md` + `./agents/*.md` — プロジェクトローカルのエージェント（両方の深さ）
2. `~/.claude/agents/**/*.md` + `~/.claude/agents/*.md` — グローバルエージェント（両方の深さ）

すべての場所からの結果はマージされ、エージェント名で重複排除される。同名の場合、プロジェクトローカルのエージェントがグローバルエージェントより優先される。ユーザーが指定した場合、カスタムパスも使用可能。

## 動作の仕組み

### ステップ1: 利用可能なエージェントの検出

上記の探索順序でエージェントディレクトリをGlobする。READMEファイルは除外。見つかった各ファイルに対して:

- **サブディレクトリレイアウト:** 親フォルダ名からドメインを抽出
- **フラットレイアウト:** すべてのファイル名プレフィックス（最初の `-` より前のテキスト）を収集。2つ以上のファイル名に含まれるプレフィックスのみドメインとして認定（例: `engineering-security-engineer.md` と `engineering-software-architect.md` は両方 `engineering` で始まる → Engineeringドメイン）。固有のプレフィックスを持つファイル（例: `code-reviewer.md`、`tdd-guide.md`）は「General」にグループ化
- 最初の `# 見出し` からエージェント名を抽出。見出しがない場合、ファイル名から名前を導出（`.md` を除去、ハイフンをスペースに置換、タイトルケース化）
- 見出し後の最初の段落から一行の要約を抽出

すべての場所を探索してもエージェントファイルが見つからない場合、ユーザーに通知: 「エージェントファイルが見つかりません。確認済み: [探索パス一覧]。期待: これらのディレクトリ内のmarkdownファイル。」その後停止。

### ステップ2: ドメインメニューの表示

```
利用可能なエージェントドメイン:
1. Engineering — Software Architect, Security Engineer
2. Marketing — SEO Specialist
3. Sales — Discovery Coach, Outbound Strategist

ドメインまたは特定のエージェントを選択してください（例: "1,3" または "security + seo"）:
```

- エージェントがゼロのドメイン（空のディレクトリ）はスキップ
- ドメインごとのエージェント数を表示

### ステップ3: 選択の処理

柔軟な入力を受け付ける:

- 番号: "1,3" でEngineeringとSalesの全エージェントを選択
- 名前: "security + seo" で検出されたエージェントにファジーマッチ
- "all from engineering" でそのドメインの全エージェントを選択

5つ以上のエージェントが選択された場合、アルファベット順にリスト表示し、絞り込みを依頼: 「N個のエージェントが選択されました（最大5個）。残すものを選ぶか、'first 5' でアルファベット順の最初の5つを使用してください。」

選択の確認:

```
選択済み: Security Engineer + SEO Specialist
作業内容を教えてください（タスクを記述）:
```

### ステップ4: エージェントの並列実行

1. 選択された各エージェントのmarkdownファイルを読み取る
2. タスクの説明がまだ提供されていない場合、入力を求める
3. Agent toolを使用してすべてのエージェントを並列実行:
   - `subagent_type: "general-purpose"`
   - `prompt: "{エージェントファイルの内容}\n\nタスク: {タスクの説明}"`
   - 各エージェントは独立して実行 — エージェント間通信は不要
4. エージェントが失敗した場合（エラー、タイムアウト、空の出力）、失敗をインラインで記録（例: 「Security Engineer: 失敗 — [理由]」）し、成功したエージェントの結果で続行

### ステップ5: 結果の統合

すべての出力を収集し、統一レポートを提示:

- エージェントごとにグループ化された結果
- 以下をハイライトする統合セクション:
  - エージェント間の合意点
  - 推奨事項間の対立や緊張
  - 推奨される次のステップ

1つのエージェントのみ選択された場合、統合をスキップして出力を直接提示。

## ルール

- **動的検出のみ。** エージェントリストをハードコードしない。ディレクトリ内の新しいファイルはメニューに自動表示される。
- **チームあたり最大5エージェント。** 5つ以上は効果が逓減し、トークン使用量が過大になる。選択時に強制する。
- **並列実行。** すべてのエージェントは同時に実行 — Agent toolの並列呼び出しパターンを使用する。
- **並列Agentコール、TeamCreateではない。** このスキルは独立した作業に並列Agent toolコールを使用する。TeamCreate（エージェント間の対話のためのClaude Codeツール）はエージェントが議論し合う必要がある場合にのみ必要。

## 例

```
ユーザー: team builder

Claude:
利用可能なエージェントドメイン:
1. Engineering (2) — Software Architect, Security Engineer
2. Marketing (1) — SEO Specialist
3. Sales (4) — Discovery Coach, Outbound Strategist, Proposal Strategist, Sales Engineer
4. Support (1) — Executive Summary

ドメインまたは特定のエージェントを選択してください:

ユーザー: security + seo

Claude:
選択済み: Security Engineer + SEO Specialist
作業内容を教えてください。

ユーザー: ローンチ前にNext.jsのECサイトをレビューして

[両エージェントが並列で実行され、それぞれの専門分野をコードベースに適用]

Claude:
## Security Engineerの所見
- [所見...]

## SEO Specialistの所見
- [所見...]

## 統合
両エージェントの合意点: [...]
緊張点: セキュリティはインラインスタイルをブロックするCSPを推奨、SEOはインラインスキーママークアップが必要。解決策: [...]
次のステップ: [...]
```
