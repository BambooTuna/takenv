# チームビルダー

エージェントペルソナ（markdown ファイル）からチームを対話的に構成し、協調実行するメニュー。ユーザーはリーダーとして指示と判断に徹し、選択されたエージェントがチームメートとして実装・レビュー・議論を行う。

## 使用場面

- 複数のエージェントペルソナでチームを構成したい場合
- メンバーに実装を任せ、自分は指示と判断に徹したい場合
- エージェント同士が議論・相互レビューする必要がある場合
- 異なるドメインからアドホックチームを構成したい場合（例: DDD + フロントエンド + LLM）

## 前提条件

- エージェントファイルはペルソナプロンプトを含む markdown ファイルであること
- frontmatter の `name` がエージェント名、`description` が説明として使用される

エージェントファイルの探索場所はプロジェクトローカルの `./agents/**/*.md` + `./agents/*.md` のみ（グローバル ~/.claude/agents/ は廃止済み）。

フラットとサブディレクトリの両方のレイアウトに対応:

- **サブディレクトリレイアウト** — ドメインは親フォルダ名から推定（例: `agents/ddd/katojun.md` → DDD）
- **フラットレイアウト** — ファイル名プレフィックス（最初の `-` より前）を収集し、2 つ以上のファイルが共有するプレフィックスをドメインと認定。固有プレフィックスのファイルは「General」に分類（例: `agents/ddd-katojun.md`, `agents/architect.md` → General）

## 動作の仕組み

### ステップ 1: 利用可能なエージェントの検出

`./agents/` を Glob する（README は除外）。各ファイルからドメイン・名前・説明を抽出する（frontmatter → 最初の見出し → ファイル名の順でフォールバック）。エージェントファイルが見つからない場合はユーザーに通知して停止。

### ステップ 2: ドメインメニューの表示

```
利用可能なエージェントドメイン:
1. DDD (2) — かとじゅん, 増田亨
2. Frontend (2) — mizchi, catnose
3. LLM (1) — うみゆき

ドメインまたは特定のエージェントを選択してください（例: "1,2" または "katojun + mizchi"）:
```

エージェントがゼロのドメインはスキップし、ドメインごとの人数を表示する。

### ステップ 3: 選択の処理

柔軟な入力を受け付ける: 番号（"1,2"）、名前のファジーマッチ（"katojun + mizchi"）、"all from ddd"。5 つ以上選択された場合はリスト表示して絞り込みを依頼する（最大 5）。選択確定後、タスク内容を尋ねる。

### ステップ 4: チームの起動

1. **TaskCreate で各メンバーの担当タスクを作成する。** タスク説明にはユーザーの要求を分解した具体的な作業内容を書き、依存関係があれば設定する。ファイル競合を避けるため、タスク分割時にファイル所有を明確にする
2. **選択された各エージェントを Agent ツールで名前付きスポーンする**（独立しているので 1 メッセージで並列に）:

   ```
   Agent({
     name: "{エージェント名}",
     prompt: "{エージェントファイルの内容}\n\n## チームでの役割\nあなたはチームメートとして参加しています。\n- 担当タスクを TaskList で確認し、TaskUpdate で in_progress にして作業開始\n- 他のメンバーとは SendMessage（to: 相手の名前）で直接議論できる\n- 作業完了時は TaskUpdate で完了をマークし、SendMessage で main に成果を報告\n- 判断が必要な場合は SendMessage で main に確認\n\n## タスク: {タスクの説明}"
   })
   ```

3. **リーダー（自分 = Claude）はオーケストレーションに徹する。** TaskList で進捗を監視し、メンバーからの質問はユーザーに判断を仰ぎ、メンバー間の対立はユーザーに報告して裁定を求める

### ステップ 5: 結果の統合

すべてのタスク完了後、統一レポートを提示する:

- メンバーごとにグループ化された成果
- 統合セクション: 合意点、推奨事項間の対立（あれば）、推奨される次のステップ

1 つのエージェントのみ選択された場合は統合をスキップして出力を直接提示。

## ユーザーの役割: リーダー

- **指示**: チームへのゴールと方針を示す
- **判断**: メンバーからの質問・確認に回答する
- **承認**: メンバーの成果物を承認/差し戻しする
- **調停**: メンバー間の意見対立を裁定する

ユーザーが自ら実装・調査を行う必要はない。すべてチームメートが実行する。

## ルール

- **動的検出のみ。** エージェントリストをハードコードしない。ディレクトリ内の新しいファイルはメニューに自動表示される
- **チームあたり最大 5 エージェント。** 協調オーバーヘッドとトークン使用量を抑えるため、選択時に強制する
- **メンバー間の直接対話を活かす。** 単発の並列 Agent 呼び出しで完結させず、名前付きスポーン + SendMessage で相互レビュー・議論をさせる
- **リーダーはオーケストレーションのみ。** 実装・調査はすべてチームメートに委譲する
