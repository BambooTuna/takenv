スライド作成は「白いキャンバスに要素を座標指定で配置する」という根本的な考え方で行う。

**Why:** 推定値や曖昧な配置だと意図せず要素が重なる・はみ出すミスが頻発した。座標を厳密に管理することで、意図した重なりだけを生み出せる。何より「伝えたい情報が最も視覚的に伝わるか」を基準に全てを言語化して考えられる。

**How to apply:**
ユーザーが「座標フレームワークで」「座標管理スライド構成法で」と指示したとき、以下の原則一式でスライドを作る。

## キャンバスと要素の構造

```
白いキャンバス（幅×高さ）
  └─ 要素を重ねて配置
       └─ 各要素 = 位置(x,y) + サイズ(w,h) + z座標 + 色 + 枠線
            └─ テキスト要素の場合
                 └─ 段落 → ラン（フォント名 + サイズ + 色 + 太字）
```

## 要素は10種類

矩形、テキストボックス、表、グラフ、線、図形、矢印、画像、グループ、意図的な余白

※「意図的な余白」は独立要素としてオブジェクト化せず、`MARGIN_X` / `MARGIN_Y` / `GUTTER` などレイアウト定数で表現する。配置の隙間が "意図的" であることを定数名で明示すること。

## 共通属性

- **位置(x, y)**: 要素の左上座標
- **サイズ(w, h)**: 幅と高さ
- **z座標**: 前面/背面の重なり順
- **背景色**
- **枠線**: 有無/色/太さ/種類（実線/破線/点線）
- **回転**

## テキストの特殊事項

- PPTXでは1つのランに **latin（英数字用）とea（日本語用）の2つのフォントタグ** がある
- 両方設定しないとフォント崩れが起きる
- python-pptxの場合、etreeで`<a:ea typeface="...">` を直接設定する必要がある

## テキストのサイジング目安

初期見積もり用の係数（Noto Sans JP 想定）。w/h 再計算時は必ずこの計算を経由し、目分量を禁止する。

- **全角 1 文字の幅** ≈ フォントサイズ(pt) × 0.0139 inch（= pt/72）
  - 例: 24pt 全角 = 約 0.33 inch/文字、16pt 全角 = 約 0.22 inch/文字
  - ボックス幅は安全側に +10% のマージンを取る
- **半角英数 1 文字の幅** ≈ フォントサイズ(pt) × 0.0075 inch
  - 例: 24pt 半角 = 約 0.18 inch/文字
- **1 行の高さ（行間込み）** ≈ フォントサイズ(pt) × 0.0139 inch × line_spacing
  - 例: 24pt × line_spacing=1.3 = 約 0.25 inch/行
- **line_spacing のデフォルト**: 1.3（本文）/ 1.15（見出し）

実測で描画した結果、この初期値で収まらなければ再調整する。

## 固定ルール

- **フォント**: Noto Sans JP に統一（latin/ea両方）
- **最小フォントサイズ**: 14pt
- **全テキストボックス**: `auto_size = MSO_AUTO_SIZE.SHAPE_TO_FIT_TEXT` に統一
- **座標管理**: 全要素は明示的な(x, y, w, h)を持つ。推定値禁止
- **次の要素のy** = 前の要素の(y + h) + 明示的margin
- **はみ出し検知**: 配置時に SLIDE_HEIGHT を超えないかチェック
- **レイアウト定数**は1箇所で集中管理
- **中央配置要素**: `vertical_anchor = MSO_ANCHOR.MIDDLE` を明示設定（デフォルトはTOPで上に詰まる）。SHAPE_TO_FIT_TEXTだとボックス高さがテキストに合わせて縮むため、中央揃えしたい場合は `auto_size = NONE` と組み合わせる
- **テキストボックス流用時の注意**: 既存のテキストボックスをコピーして中のテキストを差し替える場合、テキスト長・行数に応じて**wとhを必ず再計算**する。SHAPE_TO_FIT_TEXTは縦方向のみ自動拡大、横方向は固定。長いテキストは折り返してはみ出す。例: 「NTTデータ」(5文字) → 「NECソリューションイノベータ」(12文字、2.4倍幅必要)で起きたミス
- **改行位置**: 長いテキストを折り返すときは、文節や意味の切れ目（区切りのいい位置）で改行する。中途半端な位置で切らない。例:
  - 社名: 「NECソリューション / イノベータ」（音節・命名要素の切れ目）
  - 社名+部署: 「株式会社日立製作所 / システム＆サービス / ビジネス統括本部」（法人名 / 事業名 / 組織単位）
  - コピー: 「業務自動化と / 意思決定スピードの両立」（助詞「と」の後）
  - 元テキストの全角/半角スペースは意味の切れ目として改行に置換してよい
- **テキスト収まり対処の優先順位**: ①まず w/h を再計算してボックスを広げる → ②それでも周囲との兼ね合いでスペースに限界がある場合のみ、14pt を下限にフォントサイズを縮小する。いきなりフォント縮小に逃げない
- **折り返し行数の判断**: 1 行で w 上限内に収まるなら 1 行のまま（シンプル優先、視覚的重量の変化を抑える）。1 行で超過するときのみ折り返す。折り返し時は「最長行が w 上限内」になる最小行数を選ぶ（2 行 → 3 行…）。美観目的で不要な折り返しは入れない
- **line_spacing の適用区分**: 見出し（社名・タイトル・セクション見出し・番号バッジなど文書構造上のラベル）は 1.15、本文（複数行の説明文・リード文・箇条書き）は 1.3。社名単体のボックスは見出し扱い
- **+10% マージンの意味**: フォントメトリクスの描画差異（NotoSansJP の実幅は理論値より 3-7% 広い）＋行末が ボックス端に貼り付くのを避ける余裕。収まり計算時は必ず乗せる

## 配置の判断基準

「**伝えたい情報が最も視覚的に伝わるか**」を常に問う。

- 大きさ・色のコントラスト → 0.1秒で目に入る
- 位置関係 → 0.5秒で関係性が分かる
- テキストの読み取り → 数秒で内容を理解

| 伝えたいこと | 使う属性                           |
| ------------ | ----------------------------------- |
| 重要         | 大きいフォント/太字/赤など目立つ色 |
| 同じグループ | 近い位置/同じ背景色の矩形で囲む    |
| 違いがある   | 離れた位置/異なる色                |
| AからBへ変化 | 左→右配置/矢印で接続               |
| 量の大小     | 要素の面積（棒の長さ/円の大きさ）  |
| 時間の流れ   | 左→右、または上→下に順序配置       |
| 補足・注釈   | 小さいフォント/グレー/下方配置     |

## 副次的効果

このフレームワークで作ると:

- 意図せず要素が重なるミスがなくなる
- 意図した重なりだけを生み出せる
- 全てを言語化して設計できる
