# 指示を実行で確かめる

1. 評価対象と、現実的な通常ケース・境界ケースを決める。実行前に期待結果と重大な失敗条件を記録する。
2. 新規 subagent に対象指示とタスクを渡して実行させる。作者の期待や改善履歴は渡さない。合格条件は実行者に正解を誘導しない形にし、細かい採点基準は評価側が持つ。
3. 成果物・ツール結果を評価側で確認する。実行者には、迷った文言、自分で補った判断、やり直しを報告させる。自己申告と実測を分ける。
4. 失敗の原因に対応する指示だけ直し、新しい実行者で再確認する。変更した場合は未使用ケースも試し、評価例への過適合を確認する。

重大な条件を満たし、残る曖昧さが成果を左右しなくなれば終了する。時間やツール数は参考情報で、短縮そのものを目的にしない。取得できない数値を捏造しない。タスクに見合う反復回数に留める。

## 構造審査

実行前に、または実行が適さない対象では、新規 subagent にテキストの整合性を確認させる。description と本文の範囲、相反する条件、存在しない参照、不要な停止・権限拡大を具体的な箇所とともに報告させる。修正案は差分で作ると検討しやすい。

構造審査・模擬判断・実ツール実行は区別して記録する。subagent を利用できなければ自己確認まで行い、独立評価は未実施と報告する。評価手段の不足を理由に、依頼された編集や成果物作成まで停止しない。
