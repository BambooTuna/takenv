# x-ops — X 運用方針スキル

このスキルは **X 上の運用方針・ペルソナ・目的** を保持する。実 API 操作は必ず `xurl` スキルに委譲する。

---

## 起動条件

以下のいずれかに該当する場面で、まずこのスキルを読み込むこと:

- 投稿・返信・引用・DM の**下書き作成**
- タイムライン / メンション / 検索結果の**要約・意思決定**
- トレンド・競合・採用候補の**情報収集**
- X 上での**発信戦略の相談**

単発の読み取りや、ユーザーが明示的に指示した単発操作は `xurl` 単独で十分。

---

## ペルソナ参照ルール（重要）

起動時に `persona/` ディレクトリ配下のすべての `.md` を読み込むこと。

想定ファイル構成（存在すれば利用、無ければスキップ）:

- `profile.md` — 肩書・事業・興味領域
- `tone.md` — 文体・語彙・NG ワード
- `tweet-samples.md` — 過去ツイートのサンプル（few-shot 用）
- `goals.md` — 運用目的（採用導線・プロダクト訴求など）
- `watchlist.md` — 情報収集の対象トピック・ユーザー

**ディレクトリが存在しない / 空 / ファイルが揃っていない場合、そのまま従う必要はない**。手元にある情報のみ使用し、不足分は会話中でユーザーに確認する。

---

## xurl との連携

- 実行コマンドはすべて `xurl` スキルの書式に従う（クイックリファレンス参照）
- 書き込み系（`post` / `reply` / `quote` / `dm` など）は**必ず下書きを提示しユーザー承認を得る**
- 自動投稿はしない。承認を受けてから `xurl` コマンドを実行
- API コストに留意（`xurl` スキルのコスト注意セクションに従う）

---

## 下書き作成ワークフロー

1. `persona/` 配下をすべて読み込む
2. 目的（投稿種別・ターゲット・狙い）を整理
3. `tone.md` と `tweet-samples.md` に沿った文体で**複数案**を作成
4. ユーザーに提示し、承認後に `xurl post` / `xurl reply` 等で実行

---

## 情報収集ワークフロー

1. `watchlist.md` で収集対象（トピック・ユーザー）を確認
2. 取得クエリを**1 回だけ**実行（`-n` で件数最小化）
3. ペルソナ・目的（`goals.md`）に照らして示唆を整理
4. 必要なら下書きワークフローに接続

---

## 成果物の扱い

- 下書き・分析結果は会話内で提示する（自動ファイル保存はしない）
- ユーザーが「Slack / Notion に出して」等を明示した場合のみ、該当ツールに転送
- 下書きの種として使った情報源（GitHub / 記事 / ツイート等）は必ず明記

---

## ペルソナ自己更新ワークフロー

ユーザーの指示や会話から、`persona/` 配下の `.md` を**随時更新**する。

### 更新契機と対象ファイル

| ユーザー発言/状況 | 更新対象 |
|---|---|
| 興味領域・肩書・事業の変更 | `profile.md` |
| 新しい言い回し・NG 表現の発見 | `tone.md` |
| 良い/悪いツイート例が出た | `tweet-samples.md` |
| 採用方針・訴求方針の変更 | `goals.md` |
| 新しい追跡トピック・ユーザー | `watchlist.md` |

### 更新ルール

- **小さな追記**（1〜3 行程度）は直接編集し、何を追加したか 1 行で報告
- **大きな変更**（セクション書き換え・削除・方針転換）は**変更案を提示して承認**を得る
- 編集後は `persona/` を再読み込みし、次のアクションに反映
- 機微情報（未公開情報・社内限定情報）は含めない。判断に迷えばユーザーに確認

### 自発的な提案

会話から「これは `tone.md` に足した方が良い」「`goals.md` の優先度が変わった」と気づいたら、**勝手に編集せず提案**する。ユーザーの意向に沿って初めて更新を行う。

### 初期化

`persona/` 配下が空 or 存在しない場合、初回の対話でユーザーにヒアリングしてテンプレートから埋める。ヒアリングは一度にまとめて行い、途中で止まらないようにする。
