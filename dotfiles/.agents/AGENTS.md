# 共通の作業方針

- 応答と成果物は、指定がなければ日本語。説明は結論から簡潔に書く。
- 「モック」「ざっくり」「とりあえず」は最小限の実装を意味する。
- ユーザーの依頼・合意を作業範囲の基準にする。スキルの手順を理由に、承認済みの作業を再確認しない。不明点が成果を左右するときだけ質問し、独立して進められる作業は進める。
- 意図を説明できない既存要素は、問題・影響・改善案を示す。依頼範囲なら修正し、範囲外なら提案に留める。
- 変更手段の自由度と優先順位は別。主動線・利用頻度・実害への効きで判断し、合意した制約を理由なく蒸し返さない。
- コミットは `<type>: <description>`（feat / fix / refactor / docs / test / chore / perf / ci）。

## 環境と取り扱い

- ユーザーは鈴木健夫、株式会社バク（bak.co.jp）CTO。旧称 Tavern, inc. は使わない。
- clone 先は `~/github/{owner}/{repo}`。汎用スクリプト・設定は `~/takenv` の dotfiles と Makefile に置く。
- ローカル GPU は GTX 1070 Ti（Pascal、VRAM 8GB）。Flash Attention 2 は非対応。
- `~/takenv/docker-compose.yml` の up / pull / restart はサービス名を明示する。
- 並行セッションの変更を巻き戻さない。`git reset --hard` は使わず、取り消しは自分の差分に限定する。
- Slack・Chatwork・メール等の送信は、その宛先と内容を含むユーザーの明示的な送信依頼または承認がある場合に行う。なければ送信できるドラフトまで作る。既に得た承認は取り直さない。
- 対外文書は平易な日本語で、内部 ID・内輪コメント・未確認の固有名詞や日程を載せない。見積もりは期間・マイルストーン・成果物で説明する。

## 責任者と委譲

「実装責任者」「レビュー責任者」など、責任者を立てる依頼は、担当を持つ別エージェントの起動依頼として扱う。

- 継続した相談・反証・修正の往復が必要なら Herdr agent を優先する。`HERDR_ENV=1` のとき `herdr` スキルを読み、責任者ごとに同じ workspace の tab を作る。Herdr 外なら利用可能な subagent を使い、なければ自分で担当する。
- 調査や単発レビューなど、入力と結果で完結する仕事には subagent が合う。短い作業は直接行ってよい。人数・モデル・レビュー回数は固定しない。モデルはユーザー指定、次に起動環境の既定値を使う。
- 依頼には目的、対象パス、編集範囲、完了条件、関連規約、呼び出し元を含める。責任者は結果に責任を持ち、指示の矛盾や要件を損なう懸念は根拠と代案を呼び出し元へ返す。
- 同じファイルへの並行編集を避ける。委譲先の結果が必要になるまで独立した作業を進め、統合前に完了状態・実際の差分・必要な検証を確認する。timeout / blocked は完了ではない。
- 親は子の質問や許可待ちの内容を読み、ユーザーから既に認められた範囲なら応答する。新しい権限・送信・破壊操作まで自動承認しない。
- 呼ばれた責任者は自分の担当を実行する。Herdr の責任者を再帰的に増やさず、必要な補助作業は subagent に渡す。継続対話中の担当は維持し、仕事が終わったら自分が起動した担当だけ閉じる。
